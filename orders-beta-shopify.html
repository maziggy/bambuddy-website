Bambuddy Orders: tester guide

Thank you for testing. Bambuddy Orders takes paid orders from your Shopify store, sends them to Bambuddy's print queue, and tracks them until you ship them, with tracking, from the same screen. Setup takes about 30 minutes; most of it is the Shopify part (step 3).

What you need Setup Daily use Reporting a problem Known limits

What you need

  • Bambuddy, latest daily build (ghcr.io/maziggy/bambuddy:daily). Stable 1.2.5.x and older dailies lack "Sign in with Bambuddy" and the notification link. Update Bambuddy first; Settings → Bambuddy → Test in Orders tells you if it is too old.
  • Docker with Docker Compose v2, on a machine that is always on. The one running Bambuddy is fine. 64-bit PCs (amd64) and Raspberry Pi 4/5 (arm64) both work.
  • A Shopify store where you are the owner, or a staff member allowed to develop apps.
  • A GitHub account, to pull the image.
  • Your beta licence key. We send it on Discord.

Setup

Get access to the image

The image is private during the beta.

  1. Send us your GitHub username on Discord. We give it read access to the image.
  2. On GitHub, create a token: Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic). Tick only read:packages and copy the token. A fine-grained token doesn't work for container images.
  3. On the machine that will run Orders, log in with it:
bash
echo <your token> | docker login ghcr.io -u <your GitHub username> --password-stdin

Start Bambuddy Orders

Make a folder, for example ~/bambuddy-orders, and save this in it as docker-compose.yml. If id shows numbers other than 1000 for your user and group, put yours into PUID and PGID.

docker-compose.yml
services:
  bambuddy-orders:
    image: ghcr.io/maziggy/bambuddy-orders:beta
    container_name: bambuddy-orders
    ports:
      - "8090:8090"
    environment:
      # Owner of ./data on the host (run `id` to find yours).
      - PUID=1000
      - PGID=1000
    volumes:
      - ./data:/data
    restart: unless-stopped

Start it:

bash
docker compose up -d

Open http://<this machine>:8090. The setup page asks for:

  • an admin password (at least 10 characters). It always works, even when Bambuddy is down;
  • the address of this app, as your browser reaches it, e.g. http://192.168.1.20:8090;
  • the Bambuddy address, e.g. http://192.168.1.20:8000;
  • a Bambuddy API key: in Bambuddy, Settings → API Keys → create a key with Read Status, Manage Queue and Send notifications ticked. An existing key can't be edited there, so make a new one;
  • optional, for "Sign in with Bambuddy": in Bambuddy, Settings → API Keys → Connected Apps → add an app with the callback address Orders shows you, then paste its client ID and secret. Bambuddy's own login must be on for this.

Updating later: when a new version is out, the Overview says so and Settings → Support shows what changed. In the folder with your compose file, run docker compose pull && docker compose up -d. Not restart: that keeps the old image. Your data stays in ./data.

Connect Shopify

Shopify no longer lets you create a "custom app" in the store admin (since 1 January 2026). You create one in Shopify's Dev Dashboard instead. Orders talks to Shopify with that app's client ID and secret. The secret stays on your machine and never reaches us.

  1. Open dev.shopify.com/dashboard and log in with the account that owns your store.
  2. Apps → Create app → Start from Dev Dashboard → name it e.g. "Bambuddy Orders" → Create.
  3. Open the app's Versions page. Leave the App URL at its default, choose the newest Webhooks API version, and add the Admin API scopes read_products, read_orders, read_merchant_managed_fulfillment_orders and write_merchant_managed_fulfillment_orders. Then Release.
  4. On the app's overview, Install app (Installs card) → pick your store → Install.
  5. Open the app's Settings and copy the Client ID and Client secret.
  6. In Orders, go to Settings → Shop. Enter your …myshopify.com address, the client ID and the secret, then press Save and test. It should say "Connected to <your shop>".
!
Please report exactly what happens at step 6, even when it works. Shopify only hands out a token when the app and the store belong to the same Shopify organisation, and we have only confirmed that with a development store. If the test fails with an error about the client or the grant, your store probably sits in another organisation (common when an agency or a partner account created it). Tell us, and send the error text.

Orders only reads products and paid orders, and marks orders fulfilled when you ship them. It stores no buyer names, addresses or email addresses: only the order number, items, total and ship-to country.

Activate your licence

Settings → Licence → paste the key → Activate.

Until a licence is active, Orders takes in no orders, and a red line on every page tells you why. The key works on one install. To move to another machine, use Remove from this install first.

Set up your products

Products lists your Shopify variants. For each one you sell, choose the print file from Bambuddy's library, the plate, and how many units a plate holds (or how many plates a unit needs). Files named like the SKU are suggested automatically.

Personalised items, and items without a setup, always stop in To do for you.

Daily use

  • Overview: what needs you, what's printing, what's ready to pack.
  • To do: orders that need a decision (not set up, personalised, print failed, Bambuddy error). Each has its fix right there.
  • In production: live print progress from Bambuddy.
  • To pack: printed orders with a pick list. Tick them, Ship, choose the carrier, enter tracking numbers. Shopify marks them fulfilled and, if you leave "notify" on, emails the buyer.
  • Shipped: the last shipments with tracking links.

Useful settings

  • Order processing → Send paid orders automatically. Off means every order waits in To do until you press Send. We suggest keeping it off for your first days.
  • Order processing → Start print jobs by hand in Bambuddy. On means jobs land in Bambuddy's queue staged and wait until someone starts them there. Off (the default) starts them as soon as a printer is free.
  • Order processing → Handling time. Working days until an order should ship. Orders show their ship-by day and turn red when late. The default is 3; 0 switches it off.
  • Notifications. Which events reach your phone through Bambuddy's channels. In Bambuddy, switch on Messages from connected apps for those channels.

To open Orders inside Bambuddy's sidebar, add it in Bambuddy under Settings → Sidebar Links → External links, with the Orders address. Open Bambuddy by the same address you entered in Orders: for safety, Orders refuses to be shown inside any other site, so a different hostname or IP leaves the frame empty.

Reporting a problem

On Discord, tell us:

  1. what you did and what you expected;
  2. what happened instead (a screenshot helps);
  3. Settings → Support → Download diagnostics, attached. The file holds your setup and Orders' recent log. It contains no passwords, keys or buyer data. Have a look before you send it.

Things we especially want to hear about:

  • the Shopify connection (step 3.6), and anything confusing in that setup;
  • an order that went to the wrong printer or file, or was sent twice;
  • a shipment that didn't show up as fulfilled in Shopify;
  • anything you still do by hand, outside Orders, every day.

Known limits of the beta

  • Shopify only. Etsy comes later.
  • One batch per print file per order in Bambuddy's queue. An order with three different items shows up as three groups there; Orders shows them together.
  • New orders arrive within about a minute, not instantly.
  • A whole order ships at once. Partial shipments are done in Shopify.
  • If the licence server can't be reached, Orders keeps working for 7 days.

Lost the admin password?

bash
docker exec -it bambuddy-orders reset-admin-password
